# Architecture — implemented alpha

`StreamCore` validates four visual slots, six audio channels, scaling, shared-audio identity and persistence. `SmixxStream` owns native UI and platform lifecycles. `Vendor/SmixxAudio` is a pinned local Swift package derived from Desktop; it exports `SmixxCore` and `MixerDSP`. The hardware adapter is currently app-local and still needs a clean shared-library facade.

Video adapters deliver timestamped CGImages from ScreenCaptureKit/AVFoundation or PDFKit. Per-slot generation tokens reject stale completion/frames; a bounded queue applies manual video delay. A shared StreamMedia ProgramComposition renderer supplies studio preview, the clean output window and local MP4 recording. Network encoding and virtual-camera delivery remain unimplemented. CGImage conversion at capture resolution is a correctness-first implementation; CPU/memory/performance at four simultaneous 1080p sources remains to be profiled. The queues are bounded at 18 frames per source.

Local AVPlayer audio is copied once through an audio processing tap into the mixer, then the player's normal output is silenced. The tap owns its context through Core Media's initialize/finalize lifecycle. Audio taps, hardware/process capture and each independent HAL output use the inherited single-producer/single-consumer ring boundaries. A source slot never deliberately attaches multiple audio producers. Program uses output index 0; Monitor index 3. Local recording independently consumes output index 1; index 2 remains unused.

Host-time metadata was added to capture for freshness/diagnostics, without replacing the inherited resampler. It is **not** a complete timestamp-addressed A/V pipeline. Manual frame delay is the initial compensation; automatic source synchronization remains future work; local recordings use a host-clock video timeline and a 48 kHz audio sample timeline. Local Monitor does not depend on a receiver callback.

Audio input assignments are distinct from visual sources. A duplicated application/overlapping hardware assignment is rejected on later channels. Known native meeting apps are excluded. Browser-hosted meeting return cannot be detected by the application-level capture model; the supported initial workflow uses separate apps.

Program/Monitor route changes close prior endpoints before opening replacements. Missing devices never select system defaults. Presentation, monitoring and source activation are transient; presets never restore external transmission. Stream uses its own Application Support directory and schema. Invalid files are preserved and reset requires a backup.

Remaining extraction work: generic audio facade, network Program export, robust media-seek buffer flushing, driver lifecycle manager, exhaustive source/device fault observation, automated UI/integration coverage and performance tuning. See verification for current evidence; do not infer production readiness from the architecture names.

Annotation strokes use normalized coordinates in the oriented source page/frame. ProgramComposition applies the same Fit/Fill, bounded pan, zoom, clipping and vector ink for all outputs. PDFKit thumbnails apply crop/rotation and are rebuilt for zoom. Captured PDF frames carry page/count metadata; local media frames carry AVPlayerItemVideoOutput's displayed item time. Freeze retains this immutable frame and metadata. PNG export captures composition and citation before opening the save dialog and adds its branded footer only after rendering Program. AnnotationArchive stores versioned histories and retained frames independently of source documents; source version keys combine path, size and modification time.
